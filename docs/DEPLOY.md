# Выкладка «АТТ Академия» на сервер

Инструкция для чистого сервера. Следуйте шагам по порядку. Все команды выполняются **на сервере** (по SSH), если не сказано иное. Слова в скобках объясняют термины.

Что получится: сайт и приложение открываются по адресу `https://ваш-домен`, API (сервер приложения) работает на том же адресе под `/api`, база данных PostgreSQL лежит на этом же сервере, каждую ночь делается копия базы.

## 0. Что нужно до начала

| Что | Подробности |
|---|---|
| Сервер (VPS, виртуальная машина) | **Debian 12**, в России. Для тестового запуска хватит 2 ядра, 4 ГБ памяти, 40 ГБ диска. Для боевого по ТЗ: отдельные машины под приложение (4 ядра, 8 ГБ) и под базу (4 ядра, 8 ГБ, 100 ГБ) |
| Доступ | IP-адрес, пользователь `root` и ваш SSH-ключ (вход без пароля) |
| Домен | Например `att.ваш-домен.ru`. В DNS заведите запись **A** на IP сервера. Без домена тестовый запуск тоже возможен, но по `http` и без замка в браузере (см. шаг 8) |
| Код | Репозиторий GitHub `p58nh46dsz-bit/att-app`. Если он станет закрытым, на сервере понадобится ключ доступа (deploy key) |
| Менеджер паролей | Для секретов из шага 3. **Ключ `PASSWORD_KEY` потерять нельзя**: без него сохранённые пароли не прочитать |

Персональные данные настоящих людей (студентов, преподавателей) можно вносить только на сервер **в России** (152-ФЗ). Тестовые данные можно вносить где угодно.

## 1. Подготовка сервера (один раз)

Подключитесь: `ssh root@IP-СЕРВЕРА`. Затем:

```bash
apt-get update && apt-get install -y git
git clone https://github.com/p58nh46dsz-bit/att-app.git /tmp/att-setup
bash /tmp/att-setup/deploy/setup-debian12.sh
```

Скрипт ставит Node.js 24, PostgreSQL 16, nginx (веб-сервер), certbot (бесплатный сертификат HTTPS), создаёт пользователя `att` и папки, включает файрвол (открыты только SSH, 80 и 443) и автообновления безопасности. В конце он печатает версии. Если появилась ошибка, пришлите её текст.

## 2. База данных

Создайте пользователя и базу. Пароль придумайте длинный (от 20 символов) и сохраните в менеджере паролей:

```bash
sudo -u postgres psql -c "CREATE ROLE att_app LOGIN"
sudo -u postgres psql -c "\password att_app"
sudo -u postgres psql -c "CREATE DATABASE att OWNER att_app ENCODING 'UTF8' TEMPLATE template0"
```

Команда `\password` попросит ввести пароль дважды, на экране он не виден. Postgres слушает только сам сервер (`localhost`), снаружи к базе подключиться нельзя.

## 3. Код и секреты

```bash
sudo -u att git clone https://github.com/p58nh46dsz-bit/att-app.git /opt/att
cd /opt/att/server
sudo -u att cp .env.example .env
sudo -u att chmod 600 .env
```

Сгенерируйте два секрета (каждая команда печатает длинную строку):

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # → JWT_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # → PASSWORD_KEY
```

Откройте файл `sudo -u att nano /opt/att/server/.env` и заполните так (значения подставьте свои):

```
DATABASE_URL=postgres://att_app:ПАРОЛЬ_БАЗЫ@localhost:5432/att
JWT_SECRET=первая_строка
PASSWORD_KEY=вторая_строка
PORT=3050
HOST=127.0.0.1
TRUST_PROXY=1
CORS_ORIGINS=
```

Если в пароле базы есть символы `@ : / # ?`, замените их на `%40 %3A %2F %23 %3F` (или придумайте пароль из букв и цифр). Сохраните: `Ctrl+O`, `Enter`, `Ctrl+X`.

**Сразу сохраните значения `JWT_SECRET` и `PASSWORD_KEY` в менеджер паролей.** Файл `.env` нельзя отправлять в GitHub, пересылать в чатах и копировать в общие папки.

## 4. Первый запуск: код, база, начальные данные, администратор

```bash
cd /opt/att
./deploy/deploy.sh     # скопирует сайт, поставит пакеты, создаст таблицы; в конце напишет, что сервис ещё не установлен — это нормально до шага 5
cd server
sudo -u att npm run seed:catalog      # каталог ДПО и кружков
sudo -u att npm run seed:data         # справочники: справки, консультации, шаблоны документов, новости
sudo -u att npm run create-admin      # спросит пароль администратора (не показывается на экране)
```

Пароль администратора: **не короче 12 символов, буквы и цифры**, не «1» и не «admin». Логин по умолчанию `admin`. Другой логин: `ADMIN_LOGIN=glavny npm run create-admin`.

Администратор с именем (логин строится по тому же правилу, что у преподавателей: фамилия латиницей и инициалы, например `lukinskiy.vp`), пароль придумывает сама программа и показывает один раз:

```bash
ADMIN_NAME="Фамилия Имя Отчество" ADMIN_GENERATE=1 npm run create-admin
```

Чтобы создать администратора с логином `admin`, добавьте `ADMIN_LOGIN=admin`. Если такой администратор уже есть, команда задаёт ему новый пароль.

Людей в базе нет: аккаунтов, оценок и групп нет, создаёт их администратор (шаг 10).

## 5. Запуск API (systemd — автозапуск и перезапуск при сбое)

```bash
cp /opt/att/deploy/att-api.service /etc/systemd/system/att-api.service
systemctl daemon-reload
systemctl enable --now att-api
systemctl status att-api --no-pager       # должно быть «active (running)»
curl http://127.0.0.1:3050/health          # должно ответить {"ok":true}
```

## 6. Веб-сервер nginx

Замените `att.example.ru` на ваш домен (для теста по IP см. шаг 8):

```bash
cp /opt/att/deploy/att-proxy.conf /etc/nginx/att-proxy.conf
cp /opt/att/deploy/nginx-att.conf /etc/nginx/sites-available/att
sed -i 's/att.example.ru/ВАШ-ДОМЕН/g' /etc/nginx/sites-available/att
ln -sf /etc/nginx/sites-available/att /etc/nginx/sites-enabled/att
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

`nginx -t` должен ответить `syntax is ok` и `test is successful`.

## 7. HTTPS (замок в браузере)

Домен уже должен указывать на сервер (проверка: `ping ВАШ-ДОМЕН` показывает IP сервера).

```bash
certbot --nginx -d ВАШ-ДОМЕН
```

Укажите почту для уведомлений, согласитесь с условиями, выберите перенаправление на HTTPS (redirect). Сертификат продлевается сам. Затем включите строгий HTTPS: откройте `nano /etc/nginx/sites-available/att`, найдите строку с комментарием `Strict-Transport-Security` и уберите `# ` в её начале (строка должна оказаться внутри блока `listen 443`), потом `nginx -t && systemctl reload nginx`.

## 8. Проверка

```bash
curl https://ВАШ-ДОМЕН/api/health        # {"ok":true}
```

Откройте `https://ВАШ-ДОМЕН` в браузере и на телефоне, войдите под `admin` и своим паролем. Должна открыться панель администратора. На экране входа нет демо-кнопок и быстрого входа.

**Тест без домена, по IP.** В шаге 6 вместо домена в `server_name` поставьте `_` (`sed -i 's/server_name att.example.ru;/server_name _;/' /etc/nginx/sites-available/att`), шаг 7 пропустите и открывайте `http://IP-СЕРВЕРА`. Браузер напишет «не защищено»: так и должно быть без сертификата. Пароли по такому адресу вводить можно только тестовые.

## 9. Расписание и ночные копии базы (cron — запуск по расписанию)

```bash
cat > /etc/cron.d/att <<'EOF'
17 3 * * * root /opt/att/deploy/backup.sh >> /var/log/att-backup.log 2>&1
7 * * * * root /opt/att/deploy/update-schedule.sh >> /var/log/att-schedule.log 2>&1
EOF
chmod 644 /etc/cron.d/att
/opt/att/deploy/update-schedule.sh      # первый раз вручную, должно написать «schedule ДВ-41: N days»
/opt/att/deploy/backup.sh               # первая копия вручную, должно написать «backup ok»
/opt/att/deploy/restore-test.sh         # проверка, что копия восстанавливается: «restore OK»
```

Копии лежат в `/var/backups/att`, хранятся 30 дней. **Копируйте эту папку на другую машину или в отдельное хранилище**, иначе при потере диска пропадут и база, и копии. Ключи из `.env` в копии базы не входят: храните их отдельно в менеджере паролей.

Расписание берётся с сайта колледжа (GitHub Action обновляет файлы `schedule.json` и `teacher_schedule.json`, сервер раз в час забирает их и загружает в базу):
- **преподавателю** показываются его пары из «Расписания преподавателей» (PDF по 1-2 и 3 корпусу): сравнение идёт по фамилии и инициалам, поэтому ФИО в аккаунте должно совпадать с тем, как оно напечатано на сайте (например, «Кошкин В.А.»);
- **студентам** группы показываются пары, найденные для этой группы в том же расписании (для 3 корпуса на сайте нет названий предметов, видны преподаватель и аудитория), а у группы ДВ-41 дополнительно подробное расписание групп.
Вручную запустить сбор: `python3 scripts/scrape_teachers.py --target today --back 6` (нужен `pip install pdfplumber`; `--back 6` докачивает недостающие дни прошлой недели).

На главном экране преподавателя: карточка **«Следующая пара»** (время, группа, предмет, аудитория; нажатие открывает окно с таймером до начала пары и кнопкой «Открыть журнал этой пары»), карусель кнопок (прокручивается вбок: Журнал группы, Выставить оценки, Сообщение группе, Материалы к паре, **Расписание**) и экран **«Расписание»**: вкладка «День» (Пн–Сб текущей недели, сегодня выбран) и вкладка «Неделя» (все дни недели сразу), внизу расписание звонков обоих корпусов. Нажатие на пару открывает журнал этой группы.

## 10. Первые шаги в приложении

1. Войдите администратором. Меню профиля → **«Группы»**: добавьте группы колледжа (по одной на строку или через запятую, например `ДВ-41`). Список можно пополнять в любой момент, когда колледж присылает новые группы. У каждой группы есть кнопка **«Добавить студентов»**: вставьте список (по одному на строку: фамилия, имя, отчество; можно столбец из Excel), и для каждого создастся аккаунт, а на экране появятся логины и пароли (их можно скопировать). Группу можно удалить: пустая удаляется сразу, а если в ней есть студенты, оценки или преподаватели, приложение покажет, что пропадёт, и попросит подтвердить (аккаунты студентов остаются, но без группы).
2. Меню → **«Создать учётную запись»**: создайте студентов (группа выбирается из списка) и преподавателей. Преподаватель может сам выбрать группы и предметы в своём кабинете.
3. В разделе «Пользователи» у каждого аккаунта есть **«Изменить данные»**: ФИО, группа студента (переход в другую группу сохраняет его оценки), у преподавателя ещё кафедра, должность, стаж, email, телефон и группы. Логин при этом не меняется.
4. Предметы заводить не нужно: преподаватель в «Мои группы и предметы» сам вводит название предмета, которое он ведёт у группы, или выбирает из подсказок (предметы, уже известные в базе). Оценки он может ставить только по своим предметам. Список предметов можно посмотреть командой `cd /opt/att/server && sudo -u att npm run subjects`.
5. Логин и пароль нового пользователя админ видит в списке пользователей («Показать пароль») и передаёт человеку.
6. Оценки: преподаватель открывает «Выставить оценки», выбирает группу, предмет (из своих), вид работы и дату, ставит оценки 5/4/3/2 или «н» (не явился) и нажимает «Сохранить в базу». Оценки хранятся в базе: при повторном открытии той же ведомости (та же группа, предмет, вид работы и дата) они подгружаются, повторное сохранение обновляет их, а повторное нажатие на оценку снимает её. Студент видит оценки по предметам с датами, средний балл и пропуски в разделе «Оценки».
7. Журнал посещаемости: кнопка **«Журнал группы»** (или нажатие на карточку «Следующая пара») на главном экране преподавателя открывает расписание на сегодня: пары с группой, предметом, аудиторией и временем, текущая и следующая выделены. Нажатие на пару открывает журнал этой группы с уже выбранным предметом (группа и предмет из расписания добавляются в «Мои группы и предметы», если их там ещё не было; если группы нет в списке колледжа, приложение скажет, что её должен добавить администратор). Под расписанием есть список «Другая группа». В журнале нужно выбрать предмет и дату и отметить студентов: «был» (✓), «опоздал» (оп), «не был» (н); есть кнопка «Все были». Отметки сохраняются в базу кнопкой «Сохранить в базу», при повторном открытии подгружаются, повторное нажатие на отметку снимает её. Пропуски студент видит в «Оценки» → «Пропуски».
8. Если преподаватель выставил оценку студенту из списка группы, у которого ещё нет аккаунта, аккаунт создастся сам и появится у админа с пометкой «Уточнить ФИО».

Смена пароля: в личном кабинете студента, преподавателя и администратора есть «Сменить пароль». Требования: не меньше 8 символов, и буквы, и цифры, без пробелов по краям, не содержит логин, не из списка простых («12345678», «password1» и т.п.). Те же требования действуют, когда пароль задаёт админ. После того как человек сменил пароль сам, админ его посмотреть уже не может (только сбросить).

Загрузка студентов и преподавателей списком из Excel пока не реализована.

## 11. Обновление

Когда вы отправили изменения в GitHub (после этого GitHub сам пересобирает `index.html`, подождите 1–2 минуты):

```bash
cd /opt/att && sudo ./deploy/deploy.sh
```

Скрипт подтянет код, обновит файлы сайта, применит изменения базы и перезапустит API. Если в конце написано `OK: the API answers`, всё хорошо.

**Откат.** Вернуть прошлую версию кода: `cd /opt/att && sudo -u att git log --oneline` (найдите нужную строку), `sudo -u att git checkout НОМЕР_КОММИТА`, затем `sudo ./deploy/deploy.sh`. Если новая версия меняла базу, откат кода без отката базы может не заработать: тогда восстановите базу из копии (шаг 12).

## 12. Восстановление базы из копии

```bash
systemctl stop att-api
sudo -u postgres dropdb att
sudo -u postgres createdb -O att_app att
sudo -u postgres pg_restore --no-owner --role=att_app -d att /var/backups/att/ИМЯ_ФАЙЛА.dump
systemctl start att-api
```

Файл `.env` и его секреты восстанавливать не надо: они лежат отдельно и должны остаться теми же. Если `PASSWORD_KEY` другой, сохранённые пароли станут нечитаемыми (войти по ним можно, посмотреть в админке нельзя).

## 13. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Сайт не открывается | `systemctl status nginx`, `nginx -t`, DNS (`ping ВАШ-ДОМЕН`), файрвол `ufw status` |
| Сайт открывается, вход пишет «Сервер недоступен» | `systemctl status att-api`, `journalctl -u att-api -n 50 --no-pager`, `curl http://127.0.0.1:3050/health` |
| API не стартует, в логе `JWT_SECRET is missing` или `PASSWORD_KEY` | не заполнен `/opt/att/server/.env` (шаг 3) |
| В логе `password authentication failed` | пароль или логин базы в `DATABASE_URL` не совпадает с созданным в шаге 2 |
| `502 Bad Gateway` | API не запущен (см. выше) |
| Пишет «слишком много запросов» | сработал ограничитель: подождите минуту. Если ограничитель срабатывает у всех сразу, проверьте `TRUST_PROXY=1` в `.env` и перезапустите `systemctl restart att-api` |
| Сертификат не выдаётся | домен ещё не указывает на сервер, порты 80/443 закрыты |

Логи: `journalctl -u att-api -f` (API, в реальном времени), `/var/log/nginx/error.log`, `/var/log/att-backup.log`, `/var/log/att-schedule.log`.

## 14. Безопасность: чек-лист

- [ ] Вход на сервер только по SSH-ключу, вход `root` по паролю отключён (`PermitRootLogin prohibit-password` в `/etc/ssh/sshd_config`, затем `systemctl reload ssh`).
- [ ] Пароль администратора длинный и есть только в менеджере паролей. Демо-входов в приложении нет.
- [ ] `.env` с правами `600`, секреты сохранены в менеджере паролей, в GitHub их нет.
- [ ] Копии базы выгружаются за пределы сервера, восстановление проверено (`restore-test.sh`).
- [ ] HTTPS включён, HSTS включён.
- [ ] Автообновления включены (делает `setup-debian12.sh`).

## 15. Что не готово для настоящих данных

Эти пункты нужно закрыть до внесения персональных данных людей (они есть в плане работ и ТЗ):

- согласие на обработку персональных данных и политика обработки (экран согласия при первом входе);
- решение по просмотру паролей администратором: ТЗ требует пересмотреть обратимое хранение паролей (`password_enc`) до боевого запуска;
- настоящее восстановление пароля по почте;
- резервные копии вне сервера и отдельный сервер базы данных (по ТЗ);
- репозиторий GitHub публичный, в его истории остались демонстрационные данные (в том числе фамилии из образцов документов): перед боевым запуском сделайте репозиторий закрытым или очистите историю.
